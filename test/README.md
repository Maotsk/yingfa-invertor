# Тестовые прошивки

В этой папке лежат две вспомогательные прошивки для проверки железа
и протокола — до того, как вы зальёте основную `yingfa-invertor.yaml`.

Они не нужны для работы мониторинга. Они нужны, чтобы понять,
**где именно** что-то не работает, если оно не работает.

## Зачем это нужно

Когда собираешь схему из трёх компонентов (ESP, модуль RS232-TTL,
инвертор), самое сложное — понять, на каком именно стыке проблема.
Loopback и разведка протокола разбивают задачу на независимые этапы:
сначала проверяем ESP, потом модуль, потом инвертор. И только после
того, как всё работает по отдельности, пишем основную прошивку.

## `loopback.yaml` — проверка UART-цепочки

Проверяет микроконтроллер и преобразователь отдельно, с помощью
перемычки TX-RX. Отправляет строку `HELLO_FROM_ESP` и логирует всё,
что вернулось.

**Как использовать:**

1. Залить прошивку через ESPHome Dashboard (Create device → вставить
   содержимое → Install).
2. Поставить перемычку между TX и RX **прямо на ESP8266**
   (GPIO15 и GPIO13).
3. Открыть логи. Если увидите `HELLO_FROM_ESP` — микроконтроллер жив.
4. Снять перемычку с ESP, подключить модуль RS232-TTL.
5. Поставить перемычку между **T1 OUT и R1 IN на модуле**.
6. Снова открыть логи. Если строка вернулась — модуль жив,
   преобразование уровней работает.

**Что означают сообщения в логах:**

| Сообщение | Что значит |
|---|---|
| `Получено N байт. Линия жива.` | Узел работает, идём дальше |
| `НЕТ ОТВЕТА. Проверь перемычку и пины.` | Перемычка не туда, пины не те, или модуль мёртв |
| Мусор вместо `HELLO_FROM_ESP` | Не совпадает скорость (baud rate) или проблема с линией |

**Важно:** тестовая прошивка использует те же пины (GPIO15/GPIO13),
что и основная. Заливать их одновременно нельзя — только по очереди.

## `protocol-probe.yaml` — разведка протокола инвертора

Подключается уже к инвертору. Отправляет команды QPIGS, QPIRI, QMOD
и логирует **сырые байты ответа**. Цель — подтвердить скорость, формат
пакета, CRC и паузы, прежде чем писать парсер.

**Как использовать:**

1. Собрать полную схему: инвертор → модуль → ESP.
2. Залить прошивку через ESPHome Dashboard.
3. Открыть логи — QPIGS отправится автоматически через 3 секунды
   после загрузки.
4. Или нажать кнопку **Send QPIGS** / **Send QPIRI** / **Send QMOD**
   в Home Assistant, чтобы повторить запрос.

**Что смотреть в логах:**

- `TX: QPIGS (CRC=0xXXXX)` — команда ушла с рассчитанным CRC.
- `RX[0]: 0x28 '('` — инвертор начал отвечать, первый байт — открывающая скобка.
- Строкой в конце — читаемый ответ, например `(223.5 49.9 223.5 49.9 ...`.
- `НЕТ ОТВЕТА` — проблема с распиновкой, GND или скоростью.

**Что подтверждаем:**

- Инвертор вообще отвечает?
- Скорость 2400 бод — верная?
- Формат пакета: `(` + ASCII + CRC + `0x0D`.
- Пауза между байтами — инвертор отвечает не мгновенно.
- CRC в конце пакета сходится.

## Если что-то не работает

Порядок проверки — от простого к сложному:

1. **ESP не отвечает на loopback** — проверьте перемычку и распиновку GPIO.
2. **Модуль не отвечает на loopback** — замените модуль, проверьте пайку, добавьте конденсатор 100 нФ между VCC и GND.
3. **Инвертор не отвечает на QPIGS** — проверьте GND, распиновку RJ45, попробуйте 1200 или 9600 бод.
4. **Инвертор отвечает, но CRC не сходится** — физика линии. Укоротите кабель, экранируйте, замените модуль.

Подробности — в основной статье и в `docs/protocol-notes.md`.
